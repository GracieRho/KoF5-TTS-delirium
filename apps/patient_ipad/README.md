# iPad 마이크 내부 시험

Flutter/`record`의 16 kHz mono PCM 스트림으로 기기 내 발화 **후보**를 감지합니다. 1초 이내의 휘발성 직전 버퍼와 최대 8초 후보만 메모리에 두고, 기본적으로 오디오는 폐기합니다. 시험자 본인 음성 확인을 선택하면 지원되는 iPad에서만 Apple Speech의 `requiresOnDeviceRecognition`으로 한국어 후보를 자동 전사합니다. 기기 내 한국어 인식 지원이나 권한이 없으면 전사하지 않고 후보를 자동 전송하지 않습니다. 시험자 본인 음성 후보 한 건은 최대 30초 동안 메모리에 남기며, 직접 누르면 WAV로 변환해 HTTPS `POST /internal/synthetic/audio`에 전송합니다. 별도 '글만 자동 내부 시험' 스위치를 켜면 시험자 본인 음성의 기기 내 전사에서 '수민아' 호출 또는 60초 안의 짧은 후속 질문을 판정해 `POST /internal/synthetic/text`로 **글만** 보냅니다. 이때 마이크·네이티브 전사를 먼저 중단하고 오디오 후보를 폐기합니다. 서버는 hosted LLM/TTS를 호출할 수 있습니다. 기본 글 시험은 응답 재생과 iOS 오디오 세션 해제를 확인한 뒤 듣기를 재개합니다. 동시 듣기 실험은 재생 종료 후 공유 마이크를 중단하고 일반 듣기 마이크로 전환합니다. 두 경로 모두 동의·전사·중단 상태가 확인된 경우에만 재개합니다. 수동 오디오 전송 후에는 직접 다시 켜야 합니다. 주소·내부 토큰은 화면에서 입력하고 토큰은 배경 전환 시 지웁니다. 응답 MP3는 iOS `AVAudioPlayer(data:)`로 메모리에서 재생하며, 재생 중단을 확인하지 못하면 마이크 재시작 전에 다시 중단을 시도합니다. 원본·응답 오디오는 앱 파일이나 DB에 저장하지 않습니다. 수동 오디오 전송 시 서버와 음성 공급자에는 시험 오디오가 전달될 수 있으므로 실제 환자 자료를 입력하지 마세요.

이 연결은 **자가 음성 내부 시험**입니다. 기기 내 전사와 이름/질문 규칙은 환자/TV/의료진 화자 구분이나 병실의 신뢰할 수 있는 DIRECTED 판정이 아닙니다. 철회·마이크 중단 시 네이티브 전사 취소를 확인하고, 실패하거나 확인이 지연되면 새 전사와 전송을 차단합니다. 화면의 ‘전사 중단 다시 확인’으로 취소가 확인된 뒤에만 기기 내 전사를 다시 켤 수 있습니다. 별도 '재생 중 끼어들기' 실험을 켜면 글 전용 시험 응답 중 `record`의 iOS echo cancellation을 켠 마이크를 유지하고, 새 발화 후보가 잡히면 재생 중단을 확인한 뒤 기기 내 전사로 넘깁니다. TTS 자기 잔향일 수 있으므로 이 글은 **자동으로 서버에 보내지 않고**, 시험자가 화면에서 본인 목소리였음을 직접 확인할 때에만 다음 글 turn을 보냅니다. [Apple의 동시 입출력 카테고리](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/playandrecord)와 [voice processing 설명](https://developer.apple.com/documentation/avfaudio/avaudiosession/mode-swift.struct/voicechat)에 맞춘 코드 경로이며, 실제 iPad 스피커·병실 잔향에서 TTS 자기 오탐, 화자 구분, 중단 지연을 측정하기 전에는 PRD의 자동 barge-in 달성으로 판단할 수 없습니다. 중단을 확인하지 못하면 마이크를 멈추고 새 전사/전송을 차단합니다. 환자 목소리 등록·화자 판정, 실제 보호자 음성 등록과 운영 대화도 아직 없습니다. 발화 끝의 기본 무음 창은 PRD 범위 안인 0.9초이며 `SpeechCandidateDetector.silenceMilliseconds`로 iPad 시험에서 조절할 수 있습니다. 에너지 임계값·무음 창·이름/질문 규칙은 실제 병실 평가 전에 환자 판정에 사용할 수 없습니다.

글 시험 API가 MP3 없이 응답하면 동의·foreground·마이크/전사 중단을 확인한 뒤 일반 듣기를 재개합니다. `reply=null`인 서버 거부에서는 기기 내 듣기만 유지하고 자동 글 전송을 중단합니다. 시험을 다시 시작하려면 자기 음성 동의를 철회하고 새로 확인해야 합니다. 클라우드 처리 중에도 철회할 수 있으며, 철회 뒤 늦게 도착한 응답은 듣기를 재개하지 않습니다.

합성 글 시험의 ACTIVE 질문 창은 응답 재생이 끝나 듣기를 다시 시작한 뒤 60초 무응답이면 IDLE로 닫힙니다. 그 뒤 짧은 후속 질문은 보내지 않고 이름을 다시 불러야 새 창을 엽니다. 마이크는 켜 둔 채 기기 내 후보 감지만 계속합니다. 이 고정 창과 이름 규칙은 실제 병실의 환자 활성화 판정이 아닙니다.

기기 내 전사에서 ‘그만해’ 같은 명시적 거부 후보가 확인되면 글·오디오를 서버에 보내지 않고 듣기와 자동 글 시험을 중단합니다. 마이크 재시작은 시험 자료를 폐기하고 본인 음성 동의를 새로 확인할 때까지 차단합니다. 이 어휘 검사는 팀 내부 자가 음성 경로의 안전 중단일 뿐 환자/주변 발화의 신뢰할 수 있는 구분이나 임상 거부 판정은 아닙니다.

`flutter test`, `flutter analyze`, iOS 시뮬레이터 빌드로 코드 경로를 확인할 수 있습니다. 실제 iPad의 한국어 기기 내 인식 지원·정확도, 마이크·권한·중단·재생 동작과 클라우드 왕복은 기기/공급자 설정 후 따로 검증해야 합니다. [Apple의 요청 설정 설명](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/requiresondevicerecognition)에 따라 `supportsOnDeviceRecognition`을 먼저 확인하고 `requiresOnDeviceRecognition=true`를 적용하지만, 한국어 사용 가능 여부는 기기별로 다를 수 있습니다. 이 화면은 내부/자가 음성 시험 전용이며 [안전 게이트](../../docs/delirium-familiar-voice/07-pre-patient-trial-safety-ethics-gate.md) 통과 전 실제 환자에게 사용하지 않습니다.

합성 시험에서만 빌드 시 `--dart-define=KOF5_DEVICE_SUPABASE_URL=https://<확인된-전용-프로젝트-ref>.supabase.co`로 고정한 Supabase 주소와 `sb_publishable_` 키로 iPad의 익명 기기 로그인을 시도할 수 있습니다. 고정 주소가 없으면 원격 로그인을 차단합니다. 로그인 결과의 `user.id`를 화면의 **기기 ID**로 병원 직원에게 보여주며, 직원이나 보호자의 로그인 정보는 iPad에 입력하지 않습니다. 병원에서 연결한 뒤 `api.patient_device_context`가 합성 환자 ID `00000000-0000-4000-8000-000000000975`의 활성 연결 한 건을 기기 JWT로 돌려준 경우에만 `POST /internal/synthetic/paired/{patient_id}/text`에 기기 Bearer JWT와 내부 시험 토큰으로 **글만** 보냅니다. 이 Bearer 요청은 빌드할 때 `--dart-define=KOF5_PAIRED_SYNTHETIC_API_ORIGIN=https://<확인된-API-호스트>`로 설정한 정확한 HTTPS 원점에만 보냅니다. 원점을 아직 정하지 않았다면 요청을 차단합니다. 연결 확인 전이나 로그인 시간이 끝난 뒤에는 새 글을 보내지 않고 기존 내부 글 API로 자동 전환하지 않습니다. JWT는 메모리에 최대 1시간만 두고 refresh token을 저장하지 않으며, 시험 중단·동의 철회·배경 전환 시 지웁니다. 일반 앱 경로의 로컬 Auth 주소는 작업 전용 `127.0.0.1:54341`만 허용합니다. 전용 프로젝트의 실제 익명 로그인 설정과 실기기 왕복은 별도 검증이 필요합니다.

연결된 합성 글 요청에는 기기에서 만든 보안 난수 UUIDv4 `client_turn_id`가 포함됩니다. 거부된 후보 글은 즉시 화면과 메모리에서 지우고, 수동 끼어들기 확인 대기 글은 30초 뒤 폐기합니다. 후보 확정부터 iOS 네이티브 **재생 명령 확인**까지의 지연만 측정합니다. 이것은 PRD의 첫 실제 청취 오디오 지연 측정이 아니며, 실제 iPad에서 따로 확인해야 합니다.

# 합성 예약 병원 메시지

고정 합성 환자와 현재 입원에 연결된 내부 시험자가 별도 스위치를 켠 경우에만 전면 iPad가 30초마다 기한이 된 메시지 ID를 조회합니다. 대기 메시지가 없으면 마이크를 중단하지 않고 일반 대화를 계속합니다. 대화 중에는 자동 재생하지 않으며, 메시지가 있으면 권한·직원 승인 원문을 다시 확인하고 마이크/전사 중단을 확인한 뒤 승인 원문 그대로 시험 TTS를 재생합니다. iOS 네이티브 재생 종료를 확인한 뒤에만 기기 JWT로 DB 완료 RPC를 요청합니다. 응답이 불확실하면 같은 UUIDv4 시도로 재확인하고 같은 앱 실행 중에는 음성을 반복하지 않습니다. 거부·철회·재생 실패는 완료로 기록하지 않습니다. 병원 화면의 완료 상태는 **기기의 재생 완료 보고**이며 실제 환자 청취나 임상 전달의 증거가 아닙니다. 앱 재시작 뒤 중복 방지, 정확한 예약 시각, 실제 iPad/공급자 왕복은 아직 검증되지 않았습니다([ADR-0012](../../architecture/decisions/0012-synthetic-hospital-message-device-playback-receipt.md)).

# 합성 보조 알림

별도 자가 음성 합성 시험에서만 `수민아` 이름 호출과 제한된 위험 구절을 기기 내 전사에서 확인하면, 연결된 익명 기기 JWT로 고정 합성 환자 UUID·위험 범주·중복 방지 UUID만 `api.synthetic_alert_create`에 보낸다. 전사 원문과 후보 오디오는 이 RPC에 넣지 않는다. 화자 불명·주변 발화·거부·철회·마이크/전사 중단 실패에서는 알림을 만들지 않는다. `created` 응답은 DB 기록만 확인하며 화면은 항상 기존 호출 버튼 사용을 안내한다. 실제 환자 화자 판정, 실기기 검증, 의료진 전달·확인은 아직 없다.
