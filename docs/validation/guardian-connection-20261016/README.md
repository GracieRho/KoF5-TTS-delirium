## GPT-6 Astra high 사전 검토

판정 REJECT. 연결 확인·자료 전송·기존 제출 관리가 섞여 있었다.

1. 전역 동의 하나가 모든 환자의 전송을 활성화하고 대상·버튼과 떨어져 있었다.
2. 최신 검토 결과보다 재전송 버튼이 먼저 강조됐다.
3. 내부 병원 참조를 병원 이름처럼 표시했다.
4. 제출 상세에서 기억만 보여주고 소개·음성 상태는 누락했다.
5. 최신 제출·과거 이력·철회 행동의 비중이 같았다.

## 반영

- 대상별 `HospitalConnection` 컴포넌트가 연결 대상, 최신 제출 상태·의견, 자료 보기/재전송을 순서대로 표시한다. 이전 버전은 접힌 내역으로 이동했다.
- 전송은 공용 `ResponsiveSheet`에서 대상·자료 요약·내용 확인·명시적 동의·최종 버튼을 함께 제공한다. 시트를 닫거나 다른 대상을 열면 동의를 초기화한다.
- 병원 이름을 추측하지 않는다. 기존 참조는 연결 정보/전송 대상 영역에 병원 식별 코드로 표시한다.
- 보낸 자료 상세는 제출 당시 소개·기억·보호자 제출 음성 상태를 모두 제공한다. 피해야 할 이야기와 등록 여부 미검증을 유지한다.
- 공유 철회는 버전 상세 안에서 대상을 확인한 후 실행한다. 최종 철회 전 취소할 수 있다.
- 조회·전송 오류는 지속 표시하고, 시트 안에서도 실패 결과를 확인할 수 있다. 원본 조회의 오래된 응답은 요청 소유권으로 차단한다.
- 체크박스가 위로 분리되던 공용 label 스타일 충돌을 이 화면의 동의 폼 범위에서 수정했다. 도움말 자동 펼침을 피하도록 시트 초기 포커스는 닫기 버튼에 둔다.
- DESIGN.md에 화면·전송·이력 규칙을 반영했다. API·DB·실제 재생 동작은 변경하지 않았다.

- 프론트 전체 30개 파일·81개 테스트 통과. 이 화면 10개 테스트: 동의 후 대상 전달, 닫은 뒤 동의 초기화, 환자 간 동의 분리, 오류·재시도, 빈 결과, 최신 버전 우선/이전 내역, 제출 내용 전체, 미검증 음성 상태, 철회 확인, 검토 대기·보완 요청·철회 상태를 포함한다.
- TypeScript/Vite 빌드 통과.
- 아키텍처 생성 검사·생성기 unittest 7개·diff 공백 검사 통과.
