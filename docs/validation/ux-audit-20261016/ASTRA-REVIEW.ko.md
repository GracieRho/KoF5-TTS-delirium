녹색 보호자·파란색 병원 구분, 공용 시트, 일관된 입력 구조는 유지할 만하다. 긴 설명 문단을 추가할 필요는 없다. **도움말은 `?`, 현재 차단 상태와 다음 행동은 본문** 원칙을 적용한다.

## 수정 순서와 완료 조건

1. **잘못된 안내·탐색**: 음성·인계의 목적 탭/기록 연결, 조회 실패·빈 결과 분리, 대화 가능 여부와 문구 일치. 대상 기록 도착·새로고침 복원·5초 이후에도 오류 유지·미연결 상태의 사용 가능 문구 제거로 검증한다.
2. **중복과 정렬**: 환자 메뉴 통합, 사용 계획·승인 메시지 분리, 미완료 우선/이력 분리, 오늘 집계 정의. 어제 미완료·오늘·내일·완료·보류를 섞은 자료로 검증한다.
3. **보호자–병원 데이터 연결**: 보호자·환자 입원·음성·기억·직원 검토의 소유권·상태 계약을 확정하고, 같은 허용 가상 자료가 저장 → 병원 확인 → 검토 상태까지 이어지는 최소 경로를 구현한다. 그 이후 공급자·기기를 검증한다. 같은 이름만 아닌 **동일 ID·버전** 연결을 증명하며 합성 전용 제한을 단순 해제하지 않는다.
4. **모바일·공용 마감**: 반복 행동 축소, 긴 목록 분리, 도움말 크기 수정. 390/320px·키보드·터치·긴 한글·빈/오류 상태를 확인한다.

1–2단계를 통과하면 현재 기록·계획 도구의 다음 구현을 진행할 수 있다. 보호자 → 병원 → 환자 흐름의 완료 판정은 3단계의 실제 연결 증거까지 보류해야 한다.

## 검증 한계

Astra는 이미지·접근성 자료·연결 코드·스키마를 검토했으며 구현 수정, 테스트 실행, 실제 공급자 음성 생성·기기 재생·장애 주입은 하지 않았다. 일부 탐색·새로고침 재현은 부모가 별도로 확인했다. 현재 미연결 상태를 실제 전달 성공으로 간주하지 않는다.
