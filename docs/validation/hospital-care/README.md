# 병원 돌봄 기능 검증

2026-10-15, `feat/guardian-voice-mvp`. 전용 로컬 Supabase와 가상 자료를 사용했다.

## 구현과 근거

- [NICE CG103](https://www.nice.org.uk/guidance/cg103/chapter/Recommendations), [SCCM ABCDEF](https://www.sccm.org/clinical-resources/iculiberation-home/abcdef-bundles)를 참고한 평가·관찰, 비약물 돌봄, 가족 참여와 근무 인계 흐름. 도구 문항이나 진단 알고리즘을 복제하지 않는다.
- 병동 보드·검색·병동/업무 필터, 환자 상세 5탭, 관찰/평가/주의/인계/정정·처리 기록, 담당자·기한별 돌봄 업무 생성과 수행/보류/재개, 가족 음성 계획 등록/취소.
- 등록은 환자와 현재 입원을 한 트랜잭션으로 저장한다. 등록 자격과 임상 기록 자격·담당 배정은 별도다.
- 기록은 Supabase에 저장하며 서버 작성자·시각, 변경 이력, 동시 수정 버전 검사와 RLS를 적용한다. 원본 기록은 수정·삭제하지 않고 정정을 연결한다.
- 로컬 가상 환자 6명에 초기 평가 6건·인계 6건·주의 2건, 돌봄 42건, 음성 계획 6건을 준비했다. 브라우저 검증에서 관찰 1건, 인계 1건, 수행 기록 1건, 음성 계획 2건(1건 취소)을 추가했다. 재실행 seed는 기존 편집을 덮어쓰지 않는다.

## 검증 결과

- `npm run check --prefix apps/portal_web`: 46개 테스트, TypeScript/Vite build 통과.
- `local_care_http_smoke.py`: 실제 Auth/PostgREST에서 임상 자격 없는 registrar 쓰기 거부, 담당 외 환자 거부, 도구/점수/인계 대상 검증, 원본 수정/삭제 거부, 업무 버전 충돌, 변경 전·후 기한 감사, 음성 취소, 퇴원 후 쓰기 거부, 기관 승인 없는 등록 거부, 원자적 등록/중복 거부, 로그아웃 JWT 차단. 임시 기관·계정은 finally에서 정리한다.
- 기존 Studio API 11개와 architecture 검사·생성기 7개 테스트를 함께 확인했다.
- 실제 브라우저: 환자 검색, 관찰 저장 후 재조회, 업무 수행 사유 저장, 음성 계획 등록·취소와 변경 시각 정확성, 인계 저장 후 병동 목록 반영, 환자 등록 폼을 확인했다. 390×844에서 가로 문서 넘침이 없고 환자 표/상세/시트가 반응형으로 표시된다.
- 날짜 컨트롤의 표시값과 React 상태가 어긋나던 WebKit 경로를 수정했다. 제출 시 FormData로 실제 입력 시각을 읽고 회귀 테스트를 추가했다.
- GPT-6 Astra high 재검토: 최종 HIGH/MEDIUM 없음. 권한 없음의 0건 표시, 정정 후 최신 평가/주의가 사라지는 문제, 기존 예약 환자의 승인·기기 화면 진입 회귀를 수정했다.

## 안전 영향과 한계

환자 상태·평가·주의를 기록하는 새 흐름이므로 실제 임상 사용에는 기관의 업무·평가 도구 사용·동의·보존 정책 검토가 필요하다. 화면은 진단·처방·응급 호출을 하지 않으며 주의·인계 저장은 수신자 통보가 아니다. 등록된 음성 계획은 실제 녹음 동의·복제 음성·환자 기기 준비의 확인을 대신하지 않는다.

외부 ElevenLabs/OpenAI 호출, 실제 환자/iPad 재생, EHR·호출 시스템, 원격 배포는 검증하지 않았다. 한 테이블 1,000건 이상은 성공한 일부 조회로 표시하지 않고 명시적으로 차단하며, 운영 규모에서는 서버 페이지 조회가 필요하다. 로컬 TEST 기관 권한은 30일 만료이며 원격 임상 자격을 승인하지 않는다.
