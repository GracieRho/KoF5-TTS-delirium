# Delirium Familiar Voice Companion — MVP PRD

> **문서 목적**\
> 이 문서는 섬망 환자를 위한 **가족 음성 기반 대화·지남력 지원 시스템**의 MVP 구현 기준 문서다.\
> 목표는 모델 자체를 새로 연구·학습하는 것이 아니라, **검증된 STT / LLM / Voice Cloning API를 조합하여 실제 사용 가능한 제품 흐름을 빠르게 검증하는 것**이다.

---

# 0. 한 줄 정의

**환자가 병상에서 가족과 자연스럽게 대화하는 것처럼 느끼도록, 가족의 목소리와 가족·병원 맥락을 이용해 상시 대기형 음성 대화, 지남력 메시지, 병원 메시지 전달을 제공하는 클라우드 기반 시스템.**

---

# 1. 문제 정의

섬망은 주의력과 인지 기능이 급성으로 변하는 상태이며, 입원 환자 특히 고령자와 중환자실 환자에서 흔하다.

환자는 다음과 같은 어려움을 겪을 수 있다.

- 현재 날짜와 시간을 혼동함
- 자신이 어디에 있는지 혼동함
- 치료·검사 상황을 이해하지 못함
- 낯선 병원 환경에서 불안과 초조를 느낌
- 가족이 곁에 없을 때 안정감을 얻기 어려움

기존 비약물적 중재에서는 다음이 중요하다.

- 반복적인 지남력 제공
- 익숙한 사람과의 상호작용
- 가족 참여
- 환자의 개인적 기억과 친숙한 소재 활용

그러나 현실적으로 보호자가 환자의 상태 변화, 날짜, 검사 일정, 치료 일정에 맞춰 매번 새로운 음성 메시지를 직접 녹음하는 것은 어렵다.

따라서 본 제품은 다음을 해결한다.

> **보호자의 짧은 음성 샘플을 기반으로 가족의 목소리를 재현하고, 환자의 개인적 기억·병원 정보·대화 맥락을 이용해 필요한 말을 실시간 또는 예약 방식으로 전달한다.**

---

# 2. MVP의 핵심 가설

MVP는 아래 세 가지를 검증해야 한다.

## 2.1 Familiar Voice Hypothesis

가족의 실제 목소리와 유사한 음성이 일반 TTS보다 환자에게 더 친숙하고 안정적으로 느껴지는가?

## 2.2 Context Hypothesis

단순한 일반 대화보다 다음 정보를 활용한 응답이 더 자연스럽고 유용한가?

- 가족관계
- 과거 여행
- 직업
- 좋아하는 음식
- 최근 가족 상황
- 병원 일정
- 현재 날짜·시간·장소

## 2.3 Hands-Free Interaction Hypothesis

환자가 버튼이나 UI 조작 없이 **먼저 말을 걸어도 시스템이 자연스럽게 반응**할 수 있는가?

---

# 3. MVP에서 하지 않는 것

아래 항목은 명시적으로 MVP 범위에서 제외한다.

## 3.1 F5-TTS 한국어 파인튜닝

버린다.

기존 계획:

```text
AI Hub 500시간
→ vocabulary 확장
→ text embedding tuning
→ ConvNeXt text encoder tuning
→ 일부 DiT tuning
→ full fine-tuning
→ 경량화
```

이 과정은 TTS 모델 연구 프로젝트에는 적합하지만 현재 MVP 목적에는 과도하다.

### MVP 방향

```text
보호자 음성
→ Hosted Voice Clone API
→ voice_id
→ inference 시 voice_id 사용
```

보호자마다 별도의 model checkpoint를 학습하지 않는다.

---

## 3.2 자체 GPU inference cluster

버린다.

MVP에서는 다음을 운영하지 않는다.

- CUDA worker
- GPU autoscaling
- Kubernetes
- 자체 TTS inference server
- 모델 weight 관리
- model quantization pipeline
- on-device inference

---

## 3.3 VoiceStudio를 핵심 backend로 사용

버린다.

VoiceStudio는 다음 용도로만 사용 가능하다.

- TTS 모델 비교
- 한국어 voice cloning 품질 비교
- local model playground
- 연구 참고

프로덕션 MVP backend로 사용하지 않는다.

---

## 3.4 뉴스 기반 대화

초기 MVP에서는 버린다.

뉴스는 다음 이유로 우선순위가 낮다.

- 핵심 가치 검증에 필요하지 않음
- hallucination surface 증가
- 외부 retrieval dependency 증가
- 환자에게 불필요한 자극 가능
- 최신 정보 검증 필요

---

## 3.5 완전한 의료 AI 상담

버린다.

시스템은 다음을 하지 않는다.

- 진단
- 약 복용 지시
- 검사 결과 해석
- 증상 원인 추론
- 치료 결정
- 의료진을 대신하는 판단

---

# 4. MVP 사용자

시스템에는 세 종류의 사용자가 있다.

---

## 4.1 Patient

환자는 병상 근처 태블릿을 통해 시스템과 대화한다.

환자는 앱을 조작하는 사용자가 아니라 **음성으로 상호작용하는 사용자**다.

핵심 원칙:

> 환자에게 버튼을 누르거나 “AI에게 말한다”고 인지시키지 않는다.

---

## 4.2 Guardian

보호자는 다음 작업을 한다.

- 자신의 음성 등록
- 환자와의 관계 입력
- 환자의 개인적 기억 입력
- 가족 관계 입력
- 환자가 좋아하는 소재 입력
- 피해야 할 소재 입력

---

## 4.3 Hospital Staff

병원 직원은 다음 작업을 한다.

- 환자 확인
- 금일 대화 기록 확인
- 예정된 메시지 등록
- 즉시 메시지 전달
- 지남력 관련 정보를 수정
- 특정 자동 대화 기능 on/off

---

# 5. 전체 UX

제품의 환자 경험은 **AI assistant**보다 **계속 연결되어 있는 가족과의 음성 통화**에 가깝게 설계한다.

예시:

```text
가족 목소리:
"아빠, 오늘 좀 어때?"

환자:
"오늘은 괜찮다."

시스템:
"다행이네. 점심은 먹었어?"

환자:
"응. 죽 먹었어."
```

반대로 환자가 먼저 시작할 수도 있어야 한다.

```text
환자:
"수민아?"

시스템:
"응, 왜?"

환자:
"오늘이 며칠이냐?"

시스템:
"오늘은 9월 15일 화요일이야."
```

이 **Patient-Initiated Conversation**은 필수 기능이다.
