# 병원 섬망 돌봄 업무 확장

2026-10-15. 디자인 규격은 루트 DESIGN.md, 구현 위치는 apps/portal_web/src/hospital/.

## 근거와 제품 해석

- [NICE CG103, Recommendations](https://www.nice.org.uk/guidance/cg103/chapter/Recommendations): 최근 변화를 매일 관찰·기록하고, 징후가 있으면 일반 병동에서는 4AT, 중환자실에서는 CAM-ICU 또는 ICDSC를 적절한 교육을 받은 담당자가 사용하도록 한다. 최종 진단은 적합한 임상 전문가가 담당한다.
- [SCCM ICU Liberation ABCDEF](https://www.sccm.org/clinical-resources/iculiberation-home/abcdef-bundles): 섬망 평가와 비약물 예방, 감각 보조·수면·활동·가족 참여를 연계한다.
- 위 임상 원칙을 업무 흐름으로 해석한 자체 UI이며 원본 도구 문항·알고리즘·권고문을 복제하지 않는다. 제품이 임상 진단·처방이나 응급 호출을 대신하지 않는다.

## 이번에 완성할 업무

1. 병동 업무 보드: 현재 입원 환자 수, 기록된 주의 사항, 미완료 돌봄, 가족 음성 준비·예약. 환자 검색·병동/작업 필터와 상세 진입.
2. 환자 개요: 입원·병실, 최근 평가 기록, 오늘 돌봄, 다음 음성 계획, 주의 사항을 함께 보여준다.
3. 평가·관찰: 의료진이 실제 도구로 평가한 결과와 시각·도구·관찰 내용을 저장하고 시계열로 확인. 미평가와 음성/불가 판정을 구분한다. 자동 진단 점수는 만들지 않는다.
4. 비약물 돌봄: 지남력·가족 접촉·감각 보조·수면 환경·수분/영양·활동·통증/약물 검토 의뢰의 개별 업무 생성, 기한, 수행/보류와 사유 기록.
5. 가족 음성 계획: 목적·내용·예정 시각·담당자를 등록/취소. 실제 녹음·동의·승인·기기 준비가 확인되지 않으면 재생 성공을 표시하지 않는다. 일정 등록은 재생 실행과 별도이다.
6. 주의 사항·인계: 담당자 기록, 다음 근무자에게 남길 내용과 처리 필요 여부. 외부 알림 전송과 수동 기록을 구분한다.
7. 모든 쓰기는 실제 Supabase에 저장하고 새로고침 후 유지. 보호자/무로그인/다른 기관/퇴원 이후 쓰기는 DB에서 거부한다. 변경에는 서버 작성자·시각을 남긴다.

## 화면 규격

파란 병원 테마와 기존 브랜드를 유지한다. 첫 화면은 밀도 있는 업무 보드와 환자 목록, 상세는 상단 환자 정보 + 5개 작업 탭. 보드/리스트/상세에서 같은 지표·상태 문구를 사용한다. 입력은 공용 ResponsiveSheet, 상태 안내는 공용 toast, 지속적인 제한은 해당 작업 영역에 표시한다. 테두리·간격·호버·포커스는 DESIGN.md 토큰을 사용한다. 비어 있는 탭만 추가하거나 성공을 가장하는 버튼을 만들지 않는다.

## 경계

기관의 공식 EHR·호출·투약·검사 오더·실기기 재생은 이 범위의 외부 연결이 아니다. 기록·계획·인계 기능은 작동시킨다. 외부 연결이 필요한 동작은 준비 조건과 실제 상태를 표시하며 완료로 위장하지 않는다. 실제 환자 적용에는 기관 승인과 임상·개인정보 검토가 필요하다.
