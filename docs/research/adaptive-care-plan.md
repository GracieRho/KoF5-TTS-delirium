# 적응형 보호자 인터뷰와 근거 기반 개인화 연구·개발 계획

- 작성일: 2026-10-27
- 발표 대상: 학부생·석사생 중심 AI 학회
- 상태: 계획을 먼저 원격 게시한 뒤 구현·오프라인 검증 완료. [실제 결과](validation.md)와 [실행 안내](README.md)를 참조한다. 실제 참여자·LLM·음성·임상 실험은 미실행.
- 가제: **같은 5분, 어떤 질문을 해야 가장 가족답게 위로할까?**

## 연구 질문과 주장 범위

목소리 클로닝과 설문 프롬프트를 결합한 제품에서 출발해, **적은 인터뷰 예산으로 상황별 표현 선호를 배우면서 확인되지 않은 사실을 만들지 않는 개인화 방법**을 비교한다. 인격·의도·가족 관계 전체의 복제나 섬망 치료 효과를 주장하지 않는다.

주요 가설은 적응형 질문이 고정·무작위 질문보다 미관측 상황의 표현 선호 예측을 개선하는지, 출처·시간·철회 정보를 적용한 내용 계획이 개인화 표현을 유지하면서 사실 오류를 줄이는지다. 효과가 없거나 기본 방법이 더 좋으면 그대로 보고한다.

현재 구현에는 가족 기억 입력, 짧은 답변·음성 생성, 출처별 사실과 시간 제한의 일부가 있다. 가족 작업 공간은 최대 30개 기억을 문맥에 제공한다. 이 계획의 최초 게시 시 적응형 인터뷰와 아래 평가 도구는 없었으며, 이후 별도 연구 경로에 구현했다. 새 연구 경로는 기존 환자·보호자·병원 업무 경로와 분리한다.

## 구현 경계와 병렬 작업 계약

표준 라이브러리와 기존 FastAPI/React 도구를 사용한다. 유료 생성 코드 `generate_short_reply`와 기존 `/turn`은 연구 도구에서 호출하지 않는다. 데이터·로그·실행 결과는 기본적으로 `runs/research/`에 두며 Git에서 제외한다. 공개용 가상 질문 은행·소규모 평가 픽스처만 `configs/research/`에 추적한다.

### 인터뷰 모듈

- 소유 파일: `src/kof5_tts/research/interview.py`, `configs/research/interview.json`, 관련 단위 테스트.
- 공개 함수: `load_question_bank(path=None) -> dict`, `interview_state(answers, strategy="adaptive", seed=0, budget=5, question_bank=None) -> dict`.
- 응답 기록: `[{"question_id": "…", "option_id": "…"}]`. 은행의 `elicitation`/`heldout` 분리는 선택 단계에서 강제한다.
- 결과: `next_question`(없으면 null), `answered_count`, `budget`, `done`, `predicted_style`, `uncertainty`, `heldout_predictions`. 질문은 `id`, `scenario`, `options: [{id, text}]`로 노출한다.
- 작은 가설 집합의 사전·관측 잡음·우도 가정을 명시한다. 모델이 가정한 사용자로만 평가한 결과는 현실 개인화의 증명이 아니다.

### 근거 모듈

- 소유 파일: `src/kof5_tts/research/grounding.py`, `configs/research/grounding_cases.json`, 관련 단위 테스트.
- 공개 함수: `load_grounding_cases(path=None) -> list[dict]`, `plan_reply(case, condition="proposed", style=None) -> dict`.
- 사례 입력: `id`, `profile_id`, `question`, `topic_key`, 명시적 timezone 시각 `now`, `evidence`. 채점용 `expected`는 실행 함수에 전달하지 않는다.
- 근거: 식별자·프로필·사실 key·내용·출처·승인·검증 시각·유효 구간·철회/개정 관계. 조건은 `full_context`, `rag`, `no_time`, `proposed`.
- 결과: `action`, `text`, `evidence_ids`, `claims`, `reason`. 사실 문구는 근거의 원문을 보존하고 제한된 표현만 덧붙인다. 구조화 입력과 템플릿의 범위 밖 자유 생성 검증으로 확대하지 않는다.
- 비교군도 동일 정보와 정체성·중단·의료판단 기본 정책을 받는다. proposed만 추가 최신 정보를 받지 않는다.

### 벤치마크·화면 모듈

- `scripts/benchmark_research.py`: 명시적 오프라인 재현 명령. LLM 선택이나 provider adapter를 몰래 추가하지 않는다.
- 결과에는 `synthetic/offline/template`의 실제 방법, 설정·버전·seed·입력 hash·조건별 표본수·실행시간을 포함한다.
- `/research-api/catalog`, `/research-api/interview`, `/research-api/preview`는 합성 은행·사례만 허용하고 자유로운 환자 입력이나 원격 저장을 받지 않는다.
- 서버 조건: `KOF5_RESEARCH_ENABLED=1`, Vercel 차단, loopback host/client, 동일 Origin, 작은 JSON body 제한. 기존 인증을 약화하지 않는다.
- API/UI 통합 및 공유 파일은 통합 담당이 소유한다. worker는 지정 모듈만 변경하고 다른 사람의 변경을 되돌리지 않는다.

## 실험 설계

### A. 질문 예산과 표현 선호

fixed/random/adaptive를 동일 모델·동일 질문 풀·동일 예산으로 비교한다. 입력 질문 수와 실제 소요시간을 모두 기록한다. 참여자에게 인터뷰와 별도의 미관측 상황 응답을 받는다. 질문·인물 단위 누수를 막고 사전/하이퍼파라미터 학습과 평가 참여자를 분리한다.

처음에는 동의한 성인 10–20명의 예비실험을 고려하되 통계적 검정력이 보장되는 표본 수는 아니다. 현재 자동 검증은 가상 응답자 시뮬레이션만 실행한다. 조건별 선호 예측 정확도, 블라인드 응답 선호, 인터뷰 시간, 질문 수를 기록하고 참여자 단위 paired bootstrap으로 차이와 구간을 보고한다. 반복 seed·여러 질문을 독립 참여자로 세지 않는다.

### B. 개인화와 사실 오류

정상·정보 부재·철회·만료·미래·변경·상충·다른 가족·정체성·거부·의료판단 사례를 포함한다. 강한 전체 문맥 baseline, 일반 검색, 시간 처리 제거, 제안 방법을 비교한다. 답변 가능 사례에 응답한 비율(coverage), 응답한 주장 중 오류(selective risk), 최신 유효 사실 정답률과 표현 준수를 함께 보고한다. 전부 거절해 오류율만 낮추는 결과를 성공으로 판정하지 않는다.

손으로 작성한 정답 근거와 기대 행동을 실행 코드에서 분리한다. 실제 LLM 평가 시에는 평가자 2명이 조건을 모른 채 원자적 주장 단위로 판정하고 일치도·불일치 해결 규칙을 기록한다. LLM 판정만으로 결론 내리지 않는다.

### C. 음성·요인실험

음성 친숙함×내용 개인화의 2×2 조건은 서로 아는 동의 성인 쌍으로 설계하고, 실제 환자에게 적용하지 않는다. 순서 균형화, 명시적인 AI 생성 안내, 동일 음량·문장·재생기기, 익숙한 음성 인지 여부를 기록한다. 핵심 정보(이름·시간·장소·부정) 오류는 전체 CER·자연스러움과 별도 측정한다. ASR 재전사를 단독 정답으로 사용하지 않는다.

지연은 인터뷰 계산·내용 계획의 CPU 시간, 공급자 왕복, 재생 명령, 첫 실제 청취음을 구분한다. 이번 오프라인 CPU 측정은 iPad end-to-end 지연이나 임상 지표가 아니다. 실제 소리의 시작·끝은 외부 녹음 주석을 입력받는 도구로 분석한다.

## 발표 구성

가상 보호자 A/B가 같은 상황을 다르게 표현하는 장면, 질문 몇 개 후 heldout 예측이 달라지는 장면, 저장되지 않은 방문 사실을 추측하지 않는 장면, 승인 일정의 변경·철회 후 답변이 갱신되는 장면을 준비한다. 평가 결과와 선택한 데모 장면을 구분한다. 실제 실행하지 않은 결과·합성 음성·치료 효과를 만들어 보여주지 않는다.

## 검증·전달 순서

1. 이 계획과 해당 작업 브랜치의 Vercel 자동 배포 차단 설정을 먼저 커밋·원격 게시한다.
2. 인터뷰·근거 계획·벤치마크·실험 도구·화면을 병렬 구현한다.
3. 작은 단위 테스트 → 네트워크 차단 통합 테스트 → 웹 테스트·빌드 → loopback 실제 화면 확인을 수행한다.
4. 아키텍처 생성 및 `--check`, 생성기 단위 테스트, `git diff --check`를 통과시킨다.
5. 재현 명령·실제 수치·제한·미실행 실험을 보고서에 기록하고 코드와 문서를 원격 브랜치에 게시한다. 새 연구 변경의 main 병합·배포는 별도 명시적 요청 전 실행하지 않는다.

원격 push가 Preview 배포를 발생시키지 않도록 `vercel.json`의 `git.deploymentEnabled`에 이 작업 브랜치만 false로 지정한다. 운영 main의 배포 정책은 변경하지 않는다. 공식 설정: <https://vercel.com/docs/project-configuration/git-configuration>.

## 데이터·임상·비용 제한

실제 환자·임상 음성·식별정보를 입력하거나 커밋하지 않는다. 연구 화면은 가상 예시만 사용한다. 실제 성인 자료 수집에는 별도 동의·보존·철회·음성 공개 범위가 필요하다. 현재 [Gate07](../delirium-familiar-voice/07-pre-patient-trial-safety-ethics-gate.md)의 미완료 상태를 변경하지 않는다. 건강한 성인의 개인화 선호·합성 벤치마크 성능은 섬망 감소의 근거가 아니다.

**이번 작업은 유료 API·목소리 생성/복제·배포·실제 참여자 수집을 실행하지 않는다.** 네트워크 없는 코드와 도구, 프로토콜, 합성 검증까지가 자동 실행 범위다.
