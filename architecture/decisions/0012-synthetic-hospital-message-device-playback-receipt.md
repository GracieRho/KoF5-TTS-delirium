# ADR-0012: 합성 병원 예약 메시지의 iPad 재생 완료 기록

- 상태: 제안됨
- 작성일: 2026-09-16
- 적용 범위: 고정 합성 환자의 내부 시험만
- 관련 문서: [PRD 예약 대화](../../docs/delirium-familiar-voice/02-patient-conversation.md), [병원 메시지](../../docs/delirium-familiar-voice/08-hospital-patient-registry-and-voice.md), [Gate07](../../docs/delirium-familiar-voice/07-pre-patient-trial-safety-ethics-gate.md)

## 배경

병원 직원 두 명이 원문과 예약 시각을 승인한 메시지는 현재 입원 기기에서 기한 뒤 조회할 수 있다. 기존 iPad 내부 시험은 조회와 재생을 직접 누르고, DB 상태를 `pending`에서 바꾸지 않는다. 이 상태로는 예약 시점의 자동 재생과 기기 결과를 구분해 확인할 수 없다.

## 결정 초안

기기 내부 시험자가 **예약 메시지 자동 재생**을 별도로 켠 경우에만, 연결된 iPad가 전면 상태에서 만료되지 않은 기기 권한으로 기한이 된 메시지 ID를 주기적으로 조회한다. 대화 중에는 끼어들지 않으며, 대기 조회에 메시지가 없으면 마이크를 중단하지 않는다. 메시지가 있으면 현재 입원·동의·승인 원문을 다시 확인하고 마이크/전사를 중단한 뒤, 승인 원문 그대로 가족 시험 음성 TTS와 네이티브 재생을 실행한다. 거부·철회·권한 만료·재생 중단에서는 완료를 기록하지 않는다.

iPad가 **네이티브 재생 종료를 확인한 뒤에만** 기기 JWT와 같은 시도 UUID로 DB 완료 RPC를 요청한다. 같은 시도의 재요청은 멱등 처리하고 다른 시도는 기존 완료를 덮지 않는다. 병원 화면의 `delivered`는 이 합성 경로에서 **iPad 재생 완료 보고**만 뜻한다. 환자가 실제로 들었거나 임상 메시지가 전달됐다는 증거는 아니다. 직원이 승인한 `due_at` 큐를 기기에서 조회하므로 이 메시지 경로에 별도 Vercel cron은 필요하지 않다. PRD의 지남력·기억 예약 개입은 별도 구현 대상이다.

## 검증과 후속 조건

로컬 DB 권한/멱등성·기기 타이머/철회/재생 실패 검사를 거쳐 합성 결과를 기록한다. 완료 RPC의 네트워크 결과가 불명확한 채 앱이 재시작되면 재생이 중복될 수 있다. 실제 환자 시험 전에는 기기별 복구·중복 방지, 정확한 예약 시각, 실제 청취 확인, 임상 원문 승인 및 [Gate07 네 조건](../../docs/delirium-familiar-voice/07-pre-patient-trial-safety-ethics-gate.md#23-pre-patient-trial-gate)을 따로 검증한다.
