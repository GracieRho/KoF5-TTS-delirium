# ADR-0013: 합성 병원 맥락 사실의 두 직원 원문 승인

- 상태: 제안됨
- 작성일: 2026-09-16
- 적용 범위: 고정 합성 환자의 현재 입원 내부 시험
- 관련 문서: [병원 사실 정책](0005-hospital-approved-facts-message-fidelity.md), [PRD 병원 화면](../../docs/delirium-familiar-voice/04-apps-and-backend.md), [Gate07](../../docs/delirium-familiar-voice/07-pre-patient-trial-safety-ethics-gate.md)

## 배경

기존 병원 사실은 직원 승인 상태인 행만 조회하지만, 직원이 사실을 제안하고 다른 직원이 원문과 출처를 검토하는 화면·DB 경로는 없다. 저장소 관리자 직접 INSERT로 만든 합성 사실은 제품 승인 업무를 증명하지 않는다.

## 결정 초안

고정 합성 환자의 현재 입원에 담당 배정된 **검증된 정규 직원**이 제한된 병원/병동/병실/검사·면회 일정의 짧은 원문과 `TEST-*` 합성 출처를 제안한다. 별도의 담당 직원이 같은 원문과 출처를 확인해 승인해야만 기존 병원 사실 조회·기기 병원 질문 경로에 노출된다. 자기 승인, 권한·기관 승인·입원·동의/assent·활성 시험 프로필이 빠진 요청, 안전 범주 밖 문구는 차단한다. 제안 원문·출처·작성자·승인자·시각은 뒤에서 바꾸지 않는다.

승인 사실의 합성 출처는 현재 권한 있는 병원 직원 화면에서 확인한다. 익명 기기 응답에는 출처 참조와 직원 ID를 내보내지 않는다. 이전에 승인된 `encounter_id=NULL` 병원 이름 사실은 현재 입원 담당 직원에게 계속 보이되, 입원 참조 없는 병실·일정은 허용하지 않는다. 내부 시험 사실은 오래된 병실·일정 노출을 줄이기 위해 24시간 후 자동으로 조회 대상에서 빠지게 하는 **임시 기본값**을 둔다. 실제 병원 사실의 유효기간·갱신, EHR 출처 확인, 임상 문구 승인 책임은 기관이 정해야 한다.

## 검증과 후속 조건

작업 전용 로컬 DB를 최종 migration으로 깨끗하게 재적용해 pgTAP 515개/18파일이 통과했다. 로컬 Auth/Data API에서는 직원 A 제안→직원 B 승인→같은 입원의 승인 원문·출처 조회→기기 질문 원문 조회→동의 철회 후 차단과 fixture 0건 정리를 확인했다. 병원 웹의 늦은 요청·불확실한 제출·원문/출처 불일치 검사를 포함한 Node 경합 검사도 통과했다. 이 내부 시험 계약은 실제 병원 직원 자격 발급, 환자 정보 입력, 임상 사실 검증이나 환자 대상 사용 허가가 아니다. 실제 환자 경로는 [Gate07 네 조건](../../docs/delirium-familiar-voice/07-pre-patient-trial-safety-ethics-gate.md#23-pre-patient-trial-gate)과 기관 검토가 끝나기 전까지 열지 않는다.
